## upload-document 接口修复 & Excel 支持

### Bug 原因
1. **前端 Content-Type 误设**：`project_api.js` 中 `uploadDocument` 手动设置 `headers: { 'Content-Type': 'multipart/form-data' }`，浏览器 fetch 发送 FormData 时会覆盖自动生成的 boundary，导致服务端无法解析 multipart body
2. **前端 accept 不含 Excel**：`a-upload` 组件 accept 仅有 `.pdf,.doc,.docx,.txt,.md,.pptx`，缺少 `.xls,.xlsx`

### 修复内容
1. **前端 `project_api.js`** - 移除 `uploadDocument` 中的 `Content-Type` header 设置
2. **前端 `base.js`** - `apiRequest` 中当 body 为 FormData 时，自动从 headers 中剔除 Content-Type，让浏览器自动带 boundary
3. **前端 `ProjectDetailView.vue`** - accept 添加 `.xls,.xlsx`，提示文案加"Excel"
4. **后端 `unified.py`** - Excel 解析增加 openpyxl(.xlsx) / xlrd(.xls) 兜底：Docling 失败时自动降级
5. **后端 `project_service.py`** - 400 错误信息更详细，列出所有支持的格式
6. **后端 `pyproject.toml`** - 添加 `xlrd>=2.0` 依赖

### 验证
- curl 测试 xlsx 上传：200，markdown 正确输出表格
- curl 测试不支持的文件类型：400，返回清晰错误信息

## vue-flow 依赖修复

### 问题
项目详情页报错 `Failed to resolve import "@vue-flow/core"`，原因是 `@vue-flow/core` 等包只在容器内 `pnpm add` 但未写入宿主机 `web/package.json`

### 修复
1. 在容器内重新 `pnpm add @vue-flow/core @vue-flow/background @vue-flow/controls`
2. 手动将三个依赖写入宿主机 `web/package.json`（因为 docker-compose 只 mount src/public/index.html/vite.config.js，不 mount package.json）
3. 重启 web 容器，Vite 自动 re-optimizing dependencies

### 教训
- docker-compose 中 web 容器只 mount 部分文件，`pnpm add` 在容器内执行的改动不会同步到宿主机 package.json
- 新增前端依赖后必须同时更新宿主机的 `web/package.json`

## AI 生成流程 500 错误修复

### 问题
点击"AI 生成流程"按钮报 500，日志：`AttributeError: 'OpenAIBase' object has no attribute 'ainvoke'`

### 原因
`select_model()` 返回的是 `OpenAIBase` 对象，其异步调用方法是 `model.call()`，不是 LangChain 的 `model.ainvoke()`

### 修复
- `interview_flow_service.py`：`model.ainvoke(prompt)` → `model.call(prompt)`
- `project_service.py`：`model.ainvoke(prompt)` → `model.call(prompt)`（enrich_project 方法同样问题）

### Yuxi 模型调用规范
- `select_model()` 返回 `OpenAIBase` 实例
- 同步调用：无（底层是 AsyncOpenAI）
- 异步调用：`await model.call(prompt_or_messages, stream=False)`
- 返回值：`response.content`（字符串）或 `response` 对象（有 `.content` 属性）
- 不要用 LangChain 的 `ainvoke`/`invoke`，这不是 LangChain Runnable
